## 1. Telemetry Contract
This represents the canonical JSON payload standard for EVTWIN telemetry transmission.

```json
{
  "deviceId": "DEV10025",
  "vehicleId": "EVT10025",
  "tenantId": "ORG001",
  "timestamp": "2026-08-23T15:20:10Z",
  "schemaVersion": "1.0",
  "source": "DEVICE",
  "quality": "VALID",
  
  "battery": {
    "voltage": 48.2,
    "current": 8.4,
    "temperature": 34.7,
    "soc": 78.5
  },

  "motor": {
    "rpm": 1850,
    "temperature": 42.3,
    "current": 7.8
  },

  "vehicle": {
    "speed": 31.4,
    "latitude": 16.8523,
    "longitude": 74.5815
  }
}
```

## 2. Source Identifiers
To prevent data contamination, all payloads must explicitly declare their origin:
- `DEVICE`: Actual telemetry from the IoT hardware.
- `SIMULATION`: Data generated from MATLAB/Simulink models.
- `MOCK`: Synthetic data generated for UI testing.
- `PREDICTED`: Values generated by the ML inference engine.
