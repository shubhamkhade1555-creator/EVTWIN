# DOCUMENTATION GOVERNANCE

> If any other documentation conflicts with MASTER-PRODUCT-SYSTEM-TRUTH.md, the Master Truth takes precedence until the conflict is explicitly resolved.

## 1. Source of Truth Hierarchy
1. `MASTER-PRODUCT-SYSTEM-TRUTH.md`: The absolute philosophical, technical, and product foundation.
2. `DOCUMENTATION-GOVERNANCE.md`: Defines how we document EVTWIN.
3. `implementation/*-CONTRACT.md`: Frozen API, DB, MQTT, and Telemetry contracts.
4. `architecture/*.md`: Technical designs and system boundaries.
5. Codebase: The actual implementation.

## 2. Status Labels
Every technical document must explicitly declare its implementation status near the top of the file:
- `[IMPLEMENTED]`: Currently running in production or proven via a complete vertical slice.
- `[PROTOTYPE]`: Tested on workbench or development hardware, but not production-ready.
- `[TESTED]`: Conceptually verified but pending full integration.
- `[PARTIALLY IMPLEMENTED]`: Core exists, but advanced features are missing.
- `[UNDER DEVELOPMENT]`: Actively being coded.
- `[PLANNED]`: Architected and approved for upcoming phases.
- `[PROPOSED]`: Idea phase; not approved for MVP.
- `[SIMULATION]`: Verified through MATLAB/Simulink or mock software only.
- `[FUTURE]`: Advanced roadmap items (e.g., ML predictive maintenance).
- `[TBD]`: Unknown or pending research.

## 3. Data Source Distinction
All telemetry, digital twin output, and system metrics must declare their source. Never present non-physical data as physical measurement:
- `MEASURED`: Physical sensor reading (e.g., `source: DEVICE`).
- `ESTIMATED`: Calculated logically (e.g., Power = V * I).
- `SIMULATED`: Generated by a model (e.g., MATLAB).
- `PREDICTED`: Output of an AI/ML inference engine.
- `MOCK`: Fake data generated for UI testing.

## 4. Architecture Decision Process
All architectural decisions must be vetted through the 25 Expert Disciplines defined in the Master Truth. A component is only valid if it answers:
- **WHAT:** Why does this component exist?
- **WHO:** Who uses it?
- **WHERE:** Where does it live?
- **WHEN:** When does it operate?
- **HOW:** How does it work?
- **DATA:** What data enters and leaves?
- **SECURITY:** Who can access it?
- **FAILURE:** What happens when it fails?
- **VALIDATION:** How do we know it works?
- **SCALING:** How does it evolve?
- **STATUS:** Is it implemented, prototype, planned, or future?
